# P1 编辑器能力补齐设计

## 背景与目标

Rueditor 已完成 M0–M5：项目身份、跨平台窗口、多文档工作区、基础文件读写、语言识别、折叠以及普通查找替换。P1 继续围绕“轻量级、键盘优先、不会丢失修改”的文本编辑主流程，补齐日常编辑器能力，不引入 IDE、插件、LSP、终端、云同步或大文件专用架构。

P1 的完成标准是：用户可以在每个文档中独立配置常用编辑显示行为，使用常见文本变换完成整理工作，并在普通搜索之外使用可验证的正则搜索与替换；所有会改变文档内容的操作都进入现有修订/撤销/dirty 生命周期。

## 范围

### P1-A：日常编辑设置

为每个 `Document` 增加编辑显示和输入设置，初始值采用轻量编辑器的保守默认值：

- 显示行号：开启。
- 自动换行：关闭。
- 显示空白字符：关闭。
- 智能缩进：开启。
- 自动闭合括号：开启。
- 代码折叠：沿用当前设置，默认开启。
- Tab 宽度：沿用组件默认值；P1 提供 2、4、8 三个选择，不改变已有文本内容。

设置属于文档，而不是全局单例。切换标签时，当前标签的设置必须恢复到对应的 `EditorState`；设置变化只触发视图重绘，不增加文档修订号，不使干净文档变 dirty。工具栏保留高频的折叠入口；其余设置放进“编辑设置…”弹窗或下拉面板，避免把主工具栏扩成设置面板。

每个设置都必须有明确的选中/关闭状态、键盘可达路径和可读标签。图标按钮继续提供 tooltip 和 accessibility label。设置动作至少提供：行号、自动换行、显示空白、智能缩进、自动闭合括号、Tab 宽度。

### P1-B：文本与行操作

增加面向当前文档和当前选择的命令：

- 跳转到行：输入 1-based 行号，可选列号；非法、越界输入显示可恢复的错误，不改变光标。
- 复制当前行。
- 删除当前行。
- 上移当前行。
- 下移当前行。
- 增加缩进。
- 减少缩进。
- 转为大写。
- 转为小写。
- 清理当前文档的行尾空白。

有选择时，文本变换作用于选择；无选择时，行操作作用于光标所在行。删除、移动、缩进、大小写转换和清理行尾空白必须使用现有编辑器替换/编辑入口，作为一次可撤销操作，并使文档 dirty；跳转和显示设置不修改文本、不改变 dirty 状态。执行失败时保留原文本和选择。

P1 不承诺多光标、矩形选择、Unicode 正规化或复杂语法感知格式化；这些属于后续能力。行操作以编辑器当前的 UTF-8 文本和光标位置为准，不能绕过 `EditorState` 直接替换文档实体中的字符串。

### P1-C：搜索增强

保留现有 GPUI Kit 普通文本搜索和替换，同时增加 Rueditor 自己的搜索选项状态：

- 普通文本 / 正则表达式模式。
- 区分大小写。
- 全词匹配。

搜索状态属于当前文档的搜索会话，至少包含查询、替换文本、模式和两个匹配选项；切换标签时不会把一个文档的查询选项误用到另一个文档。普通模式继续使用 GPUI Kit 的搜索能力，保证现有查找、替换、下一个、上一个和全部替换行为不回归。

正则模式使用项目已有锁文件可解析的 Rust `regex` 依赖；若 Cargo manifest 尚未直接声明，则作为 P1 的明确依赖加入，保持离线构建可用。正则编译失败时在搜索界面显示错误并禁止替换，不修改文档。正则匹配按 Unicode 字符边界工作；全词匹配只在正则模式之外叠加明确的词边界规则，规则在测试中固定。

正则替换支持 Rust `regex` crate 的捕获组替换语法。全部替换必须是一个撤销单元；替换数量为 0 时不改变文本和 dirty 状态。替换前后都保留内存内容，保存仍通过现有 P0 外部修改保护流程。

搜索界面使用现有 GPUI Kit 搜索入口和标准输入/菜单组件，不创建自定义悬浮编辑器。选项开关应在搜索界面内可见，并在关闭/重新打开时保留当前文档会话状态；Escape 关闭搜索面板后焦点回到编辑器。

## 架构与状态边界

继续由 `Workspace` 持有 `Vec<Document>`，每个文档持有自己的 `Entity<EditorState>`。不复制文本，也不为每个设置创建独立全局状态。

建议的职责划分：

- `document.rs`：新增 `EditorSettings` 和 `SearchOptions` 等纯数据状态，并由 `Document` 持有；不放 GPUI 渲染逻辑。
- `editor.rs`：新增动作类型、路径/输入解析和纯文本变换函数；纯函数优先单测。
- `workspace.rs`：负责当前文档的设置应用、光标/选择读取、行操作调度、弹窗/搜索面板入口，以及将编辑结果提交给 `EditorState`。
- `shell.rs`：注册跨平台主修饰键快捷键；快捷键名称保持动词语义，使用 `secondary-*`。
- `tests.rs`：补充纯函数测试和真实 `TestAppContext` 工作区测试。

若正则搜索需要超过当前 `EditorState` 搜索面板能表达的交互，新增小型 `SearchSession` 应放在编辑器能力边界内，由 `Workspace` 按文档 ID 持有，不修改 GPUI Kit 源码。搜索执行前将当前文本快照读出，结果以一次 `replace_all` 写回；不在渲染函数中执行匹配或修改状态。

## 交互与错误处理

- 所有高频文本操作都有按钮、菜单或快捷键之一，重要操作同时具备键盘入口。
- 设置面板使用标准 GPUI Kit overlay；关闭后恢复编辑器焦点。
- 跳转行输入非法时显示“请输入有效的行号”或“行号超出范围”，保留当前光标。
- 正则语法错误显示具体错误信息，搜索结果为空不视为错误。
- 文本变换失败或没有可作用内容时显示短状态消息，不弹出无意义确认框。
- 异步文件保存/外部修改保护逻辑不改变；搜索替换与保存并发时遵循现有 busy 状态和 revision 检查。

## 测试与验收

先写测试并确认失败，再写最小实现。测试分为四层：

1. 纯函数：行号解析、词边界、大小写转换、行尾空白清理、正则匹配/替换和错误信息。
2. 文档模型：设置按文档独立保存；设置变化不改变 revision；搜索选项不跨文档污染。
3. GPUI 工作区集成：文本/行操作更新文本、dirty 和一次撤销；跳转改变光标；正则全部替换结果正确。
4. 回归验证：现有 M0–P0 测试、格式检查、Clippy、离线测试和 release 构建全部通过。

验收必须明确区分：

- 自动化测试覆盖的行为。
- GPUI headless 窗口覆盖的行为。
- 尚需在 macOS、Windows、Linux 原生窗口人工验收的快捷键、焦点、IME、弹窗和视觉细节。

## 非目标与后续

本 P1 不实现非 UTF-8 编码转换、超大文件分块加载、分栏/分屏、文件夹搜索、项目树、插件、LSP、终端、云同步、自动保存/崩溃恢复以及 Unicode 正规化。P1 之后再依据实际使用反馈拆分这些能力，避免当前编辑器工作区承担不必要的基础设施。
