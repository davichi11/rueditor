# 轻量文本编辑器实现计划

> 执行方式：确认计划后使用 superpowers:executing-plans 在当前任务中逐项实施，每阶段验证后推进。本文件不授权开始实现。

**目标：** 使用 GPUI Kit 构建参考 CotEditor 的 macOS 轻量文本编辑器，支持可靠的文本编辑、语法高亮和代码折叠。

**架构：** 复用 Editor / EditorState 的文本、选区、撤销和显示能力，应用负责文档生命周期、文件读写与窗口组织。一个文档持有一个编辑实体，切换标签不重建实体。文件读写在后台运行，完成结果通过文档标识和修订号回到界面。

**技术：** Rust 2024、GPUI Kit 0.6.1、按需启用的 Tree-sitter 语言支持。

**需求依据：** 本任务中用户要求轻量编辑器、参考 CotEditor、高亮和折叠；已明确暂不考虑大文件。本计划中的多标签、查找替换和文档保护是建议首版范围，等待整体确认。

## 边界与实施位置

- 第一阶段面向 macOS，保留平台窗口、文件对话框、Command 快捷键和中文输入体验。
- 不包含大文件专项优化、项目树、终端、LSP、插件系统、云同步和 Rust 源码热重载。
- 保留现有 Mori 应用。建议先新增独立 Cargo binary `text-editor`，共享当前依赖，后续再决定是否迁移为独立仓库。
- 本次只新增计划，不改 Cargo 配置或源码。
- UI 使用 GPUI Kit；不自行实现文本输入、选区、撤销或语法解析器。
- 文件监听、原子保存等若需要非 UI 辅助依赖，在对应阶段说明用途，避免为小功能引入大型框架。
- 全部界面使用语义主题、相对尺寸和中文文案；源码包含职责及关键约束注释。
- 普通源码和文本为首版验收对象，不承诺 MB/GB 级容量或打开耗时指标。

## 文件与所有权

建议新增：

```text
src/bin/text-editor.rs                 窗口启动、资源和应用命令
src/text_editor/mod.rs                 编辑器功能入口
src/text_editor/workspace.rs           标签顺序、当前文档、窗口与菜单组合
src/text_editor/document.rs            文档标识、路径、编辑实体、修订和保存状态
src/text_editor/file_io.rs             解码、换行处理、后台读写与安全保存
src/text_editor/language.rs            扩展名识别、语言配置和纯文本回退
src/text_editor/search.rs              查找面板及编辑组件搜索接口适配
src/text_editor/theme.rs               编辑器主题和高亮主题
src/text_editor/tests.rs               生产视图的 GPUI 集成测试
```

`Cargo.toml` 只在执行时补充第二个 binary 和必要 feature；Mori 仍为默认运行目标，README 说明两个启动命令。

状态约束：

- 文本、选区、撤销历史由 EditorState 唯一持有，不在应用中维护同步文本副本。
- 文档拥有稳定 DocumentId、可选路径、编码、换行策略、编辑修订、最后成功保存修订和操作状态。
- Workspace 只拥有文档集合、排序、当前选择；标题、未保存标记从文档状态派生。
- 保存开始时捕获文本快照和修订；成功只标记对应修订已保存，期间的新编辑继续显示未保存。
- 异步打开按请求标识管理；失败不能替换已有文档，关闭的文档不能被延迟结果重新激活。

## 阶段 1：编辑组件能力验证

涉及：Cargo.toml、src/bin/text-editor.rs、src/text_editor/mod.rs、src/text_editor/tests.rs。

- [ ] 创建单文档原生窗口，复用 Root、Editor 和 EditorState。
- [ ] 根据当前版本源码确认高亮 feature、语言注册、折叠、搜索、撤销与选区接口，不使用猜测的 API。
- [ ] 用 Rust、Python、JSON 样例验证高亮和折叠。折叠必须覆盖括号结构和缩进结构。
- [ ] 验证中文输入法组合输入、复制粘贴、选区、撤销重做，以及关闭折叠后全文可见。
- [ ] 验证搜索定位到隐藏文本时是否需要显式 unfold_at；确认编辑折叠边界后范围是否正确。
- [ ] 记录组件缺口。若折叠或关键编辑行为存在阻断，先提供最小复现与修复方案，再推进完整界面。

验收：真实窗口内高亮与折叠均可操作，文本编辑与撤销不破坏内容。当前源码提到约 5 万行能力仅作参考，不作为首版性能保证。

## 阶段 2：单文档打开与安全保存

涉及：document.rs、file_io.rs、workspace.rs、启动入口。

- [ ] 提供新建、原生打开对话框、拖入文件、保存和另存为；取消对话框保持当前状态。
- [ ] 后台读取与写入，界面显示进行中状态，防止重复保存；不在 Render 中执行 I/O。
- [ ] 支持 UTF-8 与 UTF-8 BOM，拒绝静默替换非法字节，失败时保留原文档和未保存状态。
- [ ] 检测 LF / CRLF。混合换行需明确告知并选择统一策略，不能在用户不知情时统一文件。
- [ ] 保存采用同目录临时文件加替换流程；失败保留原文件。对只读文件、符号链接、权限保留制定明确策略，符号链接先解析真实目标，不覆盖链接本身。
- [ ] 未命名文档首次保存进入另存为；只有成功写入后更新路径和保存修订。
- [ ] 添加文件读写测试：中文往返、BOM、LF/CRLF、非法 UTF-8、失败保存、保存中继续编辑。

验收：打开 → 编辑 → 保存 → 再打开内容一致；写入失败不丢失原文件或编辑内容。

## 阶段 3：CotEditor 风格窗口与多文档

涉及：workspace.rs、document.rs、theme.rs、启动入口。

- [ ] 采用原生标题栏、紧凑工具栏、文档标签、编辑正文和底部状态栏。默认不显示侧栏。
- [ ] 状态栏显示行列、编码、换行类型、语言；语言和换行设置具备可发现入口。
- [ ] 增加标签切换、关闭标签、新建标签；每个文档保留自身滚动、选区与撤销状态。
- [ ] 同一路径重复打开定位已有标签；多文件拖入逐个处理，单个失败不影响其他文件。
- [ ] 未保存文档关闭时提供保存、放弃和取消；保存失败或取消另存为不得继续关闭。
- [ ] 退出应用逐个处理未保存文档；中途取消应停止退出。
- [ ] 支持深浅主题、字号增减与重置、自动换行开关，显示长文件名和长行时布局可用。

验收：切换标签保持编辑状态；取消关闭或退出不丢数据；窗口缩小时正文获得剩余空间，工具栏和状态栏不被挤出。

## 阶段 4：高亮与折叠产品化

涉及：language.rs、document.rs、workspace.rs、theme.rs。

- [ ] 首批支持 Rust、Python、JavaScript/TypeScript、JSON、HTML/CSS、Markdown、TOML、YAML；具体 feature 按已安装版本验证后启用。
- [ ] 按扩展名自动选择语言，并支持手动切换；未知类型进入纯文本模式。
- [ ] 集成折叠槽、折叠/展开命令。全部折叠/展开仅在组件公开能力验证通过后加入，不访问其私有状态。
- [ ] 切换语言后刷新高亮和折叠候选，清除不适用的旧折叠范围；纯文本不保留代码折叠状态。
- [ ] 验证折叠范围内剪切粘贴、撤销重做、搜索跳转、嵌套展开与保存。
- [ ] 验证选区、搜索命中与语法颜色在深浅主题下均可区分。

验收：折叠只改变显示，不改变文件内容；保存包括隐藏文本；语法错误或不完整代码不导致编辑器崩溃。

## 阶段 5：查找替换与键盘工作流

涉及：search.rs、workspace.rs、document.rs、启动入口。

- [ ] 优先复用组件搜索与替换能力，查找面板只适配产品入口与状态展示。
- [ ] 提供查找、前后匹配、替换当前、全部替换、大小写匹配和正则表达式。
- [ ] 非法正则在面板内提示，保留原文本；零长度匹配必须保证推进并终止。
- [ ] 查找结果跳转到折叠区域时展开必要范围并滚动到结果。
- [ ] 将全部替换视作一次用户操作，验证一次撤销恢复整个替换前文档；若组件无法保证，需要专项适配。
- [ ] 统一按钮、菜单和快捷键：⌘N、⌘O、⌘S、⇧⌘S、⌘W、⌘F、⌘G、⇧⌘G、⌘Z、⇧⌘Z、⌘Q。
- [ ] Escape 关闭查找面板并恢复编辑区焦点，Tab 顺序与视觉顺序一致。

验收：无匹配、非法正则、中文、多行和零长度匹配均可恢复；搜索不会改变文档未保存状态。

## 阶段 6：外部修改保护与发布验收

涉及：file_io.rs、document.rs、workspace.rs、README.md。

- [ ] 检测外部修改、删除和文件替换；使用磁盘基线并在保存前重新检查，不能只依靠监听事件。
- [ ] 外部变化且本地未修改时提示重新载入；本地存在编辑时保留本地内容，提供重新载入、另存为或显式覆盖。
- [ ] 自己保存造成的事件应更新磁盘基线，不反复弹出冲突提示。
- [ ] 加入文档状态转换和文件冲突测试，以及生产视图的关键交互集成测试。
- [ ] 完成原生窗口人工验收：中文输入、菜单快捷键、对话框取消、主题、最小窗口、折叠与多标签。
- [ ] 构建本地 macOS 应用，记录运行方式、支持语言、编码范围和已知限制；正式签名公证不属于本阶段。

验证命令：

```sh
cargo fmt --check
cargo check --bin text-editor
cargo clippy --bin text-editor -- -D warnings
cargo test --bin text-editor
cargo build --bin text-editor
cargo run --bin text-editor
```

GPUI 测试所需 test-support 配置以当前技能的 testing 文档为准；只在测试配置中开启。命令通过不替代真实窗口验收。若 Computer Use 仍无系统权限，明确列出需人工验证的项，不将其标为已通过。

## 里程碑与估算

1. 编辑核心验证：2～3 个工作日。
2. 单文档打开与保存：3～5 个工作日。
3. 多文档与原生界面：4～6 个工作日。
4. 高亮折叠产品化：3～5 个工作日。
5. 查找与键盘工作流：3～5 个工作日。
6. 文档保护与验收：4～6 个工作日。

合计约 4～6 周全职工作；现有组件缺陷可能增加时间。第 1 阶段结束后基于实际验证重新估算。

## 计划自检

- 高亮、折叠：阶段 1 验证，阶段 4 产品化。
- 参考 CotEditor 的轻量界面：阶段 3。
- 不考虑大文件：未安排分块加载、mmap、超大文件或性能目标。
- 文档安全：阶段 2、3、6，保存失败和取消均不得丢失修改。
- 原应用保护：新增独立 binary，不替换现有 Mori 入口。
- 验收证据：文件测试、GPUI 集成测试与真实窗口检查分别记录。
